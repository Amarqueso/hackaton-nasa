# Processo de trabalho

- As tarefas são as issues do GitHub, uma de cada vez.
- Ler os critérios de aceite da issue (Goal e Description) antes de começar e de novo antes de fechar.
- Fazer commits com frequência.
- Todas as issues são feitas na mesma branch, `otimizacao`. Nunca commitar nem dar push direto na `main`.

## Roles

- PM - grooms a task before anyone implements it, follows `_docs/team/pm.md`
- Engineer - implements one groomed task, follows `_docs/team/software-engineer.md`
